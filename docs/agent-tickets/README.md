# KBJS Studios — Task Tickets

Copy-paste-ready task tickets for handing work to coding agents
(Claude Code, OpenCode, Cursor, GitHub Copilot, …). Describe the task once,
give the ticket to any agent, get a consistent implementation and report back.

## Files

| File | Use for |
|---|---|
| `TEMPLATE-MASTER.md` | Full tickets: features, redesigns, multi-file work |
| `TEMPLATE-QUICK.md` | Small bugs, minor UI tweaks, one-line fixes |
| `EXAMPLE-improve-mobile-nav.md` | Filled-in example of a real master ticket |

## How to use

**Option A — web form (recommended):** open
[`new-ticket.html`](../../new-ticket.html) on the site (internal tool, not in
the navbar or sitemap). Fill the fields, hit **Send to Discord** for a compact
ticket embed, and **Copy ticket (Markdown)** to grab the full ticket text to
paste into an agent.

**Option B — file-based:** copy `TEMPLATE-MASTER.md` (or `TEMPLATE-QUICK.md`
for small stuff) into a new file in this folder: `YYYY-MM-DD-short-slug.md`.
Fill in the sections. **Required:** Ticket Information, Objective,
Requirements, Acceptance Criteria. Mark suggestions so the agent knows what
is mandatory. Hand the file to the agent — paste its contents, attach the
file, or point the agent at the path if it has repo access. The agent fills
in the Completion Report before declaring done.

## Tips for good tickets

- One ticket = one outcome. Split unrelated work into separate tickets.
- Name concrete files/pages when you know them (`contact.html`,
  `styles.css`, `tools/build_home.py`) — the agent will inspect the rest.
- Acceptance criteria should be checkable: "navbar shows 4 links at 360 px
  width", not "navbar looks better".
- Never paste secrets into a ticket. Reference the config file name instead
  (e.g. "the webhook constant in `firebase-config.js`").
- If the agent asks a blocking question, answer in the ticket file itself so
  the context stays with the task.

## Where agents should look first

The repo README describes the architecture (no build step, plain HTML/CSS/JS,
shared markup generated by `tools/*.py`). Agents with repo access should read
it before editing. Page HTML is generated — editing a page usually means
editing its generator in `tools/`, then re-running the build scripts in the
order listed in `tools/README.md`.

## Submitting to an agent

- **With repo access (preferred):** give the agent the ticket file path and
  let it inspect the codebase.
- **Without repo access:** paste the filled ticket into the chat along with
  the relevant file contents the ticket references.
